# Syranet VPN

Go-сервис управления VPN-доступом через два Telegram-бота, PostgreSQL и `sing-box` на RU-сервере. Пользователь подключается к RU по Hysteria2 или SOCKS5, а RU пересылает трафик на существующий Hysteria2-сервер NL. NL-сервер этот проект не устанавливает и не настраивает.

## Возможности

- Пользовательский бот: анкета, запрос доступа, Hysteria2-ключ, ссылка на Telegram SOCKS-прокси, статус подписки и запрос продления.
- Админский бот: одобрение и отклонение заявок, продление, приостановка и активация доступа, список пользователей и статистика. Доступ ограничен Telegram ID из `ADMIN_IDS`.
- Индивидуальные случайные credentials; в VPN-конфиг включаются только пользователи со статусом `active`/`approved` и действующей подпиской.
- Генерация полного конфига RU `sing-box` из шаблона, проверка через `sing-box check`, атомарная запись и `systemctl reload`.
- Проверка истечения подписок каждые 30 минут и уведомления администраторов перед истечением. Дедупликация уведомлений хранится в памяти и сбрасывается после перезапуска.
- Опциональный мониторинг соединений через Clash API и fallback credentials для миграции старых пользователей.

Платёжной интеграции, веб-интерфейса и публичного HTTP API нет. Боты используют long polling; webhook и входящий порт для них не нужны.

## Требования

Для серверного запуска нужны Linux с systemd, Docker с Compose, установленный на хосте `sing-box` и настроенный NL upstream. Для локальной сборки нужен Go 1.23 или новее.

Перед запуском подготовь:

- Два разных Telegram-бота и числовые Telegram ID администраторов.
- Запущенный `sing-box.service`, поддерживающий `systemctl reload sing-box`. `status` подтверждает состояние службы, но не поддержку reload; проверь unit отдельно.
- `/usr/bin/sing-box`, `/etc/sing-box/config.json`, сертификат `/etc/sing-box/cert.pem` и ключ `/etc/sing-box/key.pem`.
- Доступность RU-портов: по умолчанию UDP 443 для Hysteria2 и TCP 8443 для SOCKS5; исходящее подключение к NL — UDP 443.

Контейнер управляет службой хоста через systemd/dbus и пишет в `/etc/sing-box`. Это серверный стек: запуск приложения сразу пытается заменить VPN-конфиг данными из БД и шаблона. На новой пустой БД старый доступ сохраняется только при заполненных fallback credentials. Прочие настройки старого конфига автоматически не переносятся — сначала сопоставь их с [шаблоном](configs/singbox_template.json).

## Настройка

```bash
cp .env.example .env
chmod 600 .env
```

Заполни непустые значения `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `USER_BOT_TOKEN`, `ADMIN_BOT_TOKEN`, `ADMIN_IDS`, `RU_SERVER_ADDRESS`, `NL_SERVER_ADDRESS`, `NL_PASSWORD`. В [`.env.example`](.env.example) перечислены все env-параметры конфигурации и текущие значения по умолчанию. Несколько администраторов задаются через запятую: `ADMIN_IDS=123456789,987654321`.

`FALLBACK_HY2_PASSWORD` опционален. `FALLBACK_SOCKS_USERNAME` и `FALLBACK_SOCKS_PASSWORD` задаются вместе или остаются пустыми. Fallback-пользователи добавляются первыми и не зависят от подписок в БД.

Значения с `$`, `#` или пробелами заключай в одинарные кавычки по синтаксису Compose dotenv. Не публикуй `.env`, его резервные копии, приватные ключи и дампы БД. `.gitignore` исключает их из новых добавлений, но не снимает с отслеживания ранее добавленные файлы. Docker-контекст ограничен исходниками и поставляемыми конфигами через `.dockerignore`.

Compose читает `.env` и передаёт параметры приложению. `DB_HOST=postgres` и `DB_PORT=5432` для приложения закреплены в Compose; другие настройки применяются поверх [config.yaml](configs/config.yaml). Путь шаблона в YAML относителен к каталогу YAML; в контейнере он переопределяется на `/app/configs/singbox_template.json`. При изменении путей хоста поправь и bind mounts в Compose.

### Мониторинг соединений

По умолчанию `MONITORING_ENABLED=true`, `CLASH_API_URL=http://host.docker.internal:9090`. Однако шаблон `sing-box` слушает Clash API на **127.0.0.1 хоста**, поэтому контейнер через Docker bridge не сможет обратиться к нему только за счёт `host.docker.internal`.

До включения рабочего мониторинга обеспечь доступ контейнера к API через закрытый адрес/прокси и соответствующий `CLASH_API_URL`, либо задай `MONITORING_ENABLED=false`. Не выставляй API без защиты в интернет: приложение не передаёт токен авторизации API. Изменение controller в текущем конфиге недостаточно — сервис генерирует его заново из шаблона.

Лимит считает соединения API, а не устройства. Сопоставление с пользователями зависит от полей `metadata.user`/`metadata.specialProxy` в ответе конкретного `sing-box`. Автоматическое отключение лишних соединений по умолчанию выключено (`DISCONNECT_EXTRA_SESSIONS=false`); без проверки этих полей нельзя считать лимит устройств подтверждённым.

## Запуск на сервере

Из каталога проекта сначала проверь настройки без запуска контейнеров:

```bash
docker compose config --quiet
systemctl is-active sing-box
systemctl cat sing-box
```

Затем запусти с правами, позволяющими читать и копировать конфиг хоста и обращаться к Docker:

```bash
./deploy.sh
```

Скрипт проверяет, что служба `sing-box` активна, копирует `/etc/sing-box/config.json` в `config.json.backup.<timestamp>`, собирает образы, запускает стек и через 5 секунд проверяет состояние контейнера приложения. Бэкап содержит credentials: сохрани его с ограниченными правами. Скрипт не делает бэкап БД, не проверяет реальное VPN-подключение и не выполняет автоматический откат.

Для ручного запуска после подготовки хоста и резервной копии:

```bash
docker compose up --build -d
docker compose ps
docker compose logs --tail=100 syranet-vpn
```

PostgreSQL публикуется только на `127.0.0.1:5432`; при занятом порте измени или убери публикацию. Данные хранятся в volume `postgres_data`. [SQL-схема](migrations/001_init.sql) выполняется entrypoint PostgreSQL только при первой инициализации пустого volume. Смена `DB_*` в `.env` не меняет существующие роли/пароли/базы; автоматического мигратора в приложении нет.

После изменения `.env` применяй конфигурацию пересозданием:

```bash
docker compose up -d --force-recreate syranet-vpn
```

Обычный `docker compose restart` не перечитывает env. Не запускай `docker compose down -v` для обновления: это удаляет volume с БД.

## Проверка после запуска

1. Проверь логи PostgreSQL и приложения. При неудачной начальной синхронизации `sing-box` приложение пишет warning и продолжает работу, поэтому `running` не доказывает применение нового конфига.
2. Пройди `/start` и анкету в пользовательском боте.
3. В админском боте проверь `/pending`, одобри заявку через `/approve <user_id>`.
4. Получи `/getkey` или `/getsocks` и проверь подключение клиентом, затем приостановку/возобновление доступа.
5. Если мониторинг включён, проверь API и корректность статистики в `/info <user_id>`.

Админские команды используют внутренний `users.id`, а не Telegram ID. Остальные команды: `/users [page]`, `/reject <user_id> <reason>`, `/extend <user_id> <days>`, `/suspend <user_id>`, `/activate <user_id>`, `/stats`, `/help`. Пользовательские: `/start`, `/getkey`, `/getsocks`, `/status`, `/extend` (запрос администратору).

## Отключение fallback

После выдачи новых ключей всем пользователям:

```bash
./disable-fallback.sh
```

Скрипт запрашивает `yes`, создаёт `.env.backup.<timestamp>`, удаляет строки `FALLBACK_*` из `.env` и пересоздаёт приложение. После запуска проверь успешную синхронизацию: сама операция не доказывает, что старые ключи уже перестали работать. Также убери fallback из окружения оболочки, если экспортировала их вручную: Compose отдаёт ему приоритет над `.env`.

## Локальная разработка

```bash
go test ./...
go vet ./...
go build -o bin/vpn-service ./cmd/vpn-service
```

Бинарь не читает `.env` автоматически. Перед запуском передай параметры через окружение; для локального PostgreSQL нужны `DB_HOST=127.0.0.1`, `DB_PORT=5432`. Само приложение требует Telegram, БД и управление `sing-box`, поэтому его запуск не является автономным smoke-тестом. Для проверки сборки достаточно команд выше.

Основные файлы: [main.go](cmd/vpn-service/main.go), [конфигурация](internal/config/config.go), [генератор](internal/service/configgen.go), [управление sing-box и мониторинг](internal/service/singbox.go), [Compose](docker-compose.yml), [Dockerfile](Dockerfile). `VPN_SERVICE_PROMPT.md` и `VPN_SERVICE_UPDATE_PROMPT.md` — исторические задания; текущее поведение определяют код и этот README.

## Текущие ограничения

- Hysteria2-ссылка выдаётся с `insecure=1`, а NL TLS в шаблоне использует `insecure: true`: проверка сертификата отключена. Для строгой TLS-проверки нужны согласованные изменения шаблона и генератора ссылок.
- Неуспешный reload не откатывает уже записанный конфиг; ошибка синхронизации не откатывает изменение пользователя в БД. Проверяй логи и держи резервную копию.
- Числовые, boolean и duration env-настройки с ошибочным форматом могут молча сохранить значения из YAML/дефолтов. Используй корректные значения (`true`/`false`, `30s`, `72h`) и положительные интервалы.
- Запускай один экземпляр приложения: сессии анкеты и дедупликация уведомлений находятся в памяти, запись VPN-конфига не координируется между экземплярами.
